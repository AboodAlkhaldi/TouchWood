# Lessons: every mistake so far

Copied from the previous agents' notes on 2026-11-05. Keep it current; this copy is now the one to update.


Owner's rule (2026-09-17, restated 2026-09-20: "see and take a note about every issue or mistake or error you fall into, to never fall into it again"). **Write a new entry the moment a mistake happens — not at the end of the step.** Re-read before starting a step, and when a check fails.

## A · Process and decisions

1. **Decisions taken alone.** In Platform ~15 spec items were written [PROPOSED] and ~16 more choices appear in no spec. → Ask first, every time ([[touchwood-working-rules]] rule 1).
2. **An approved spec edited afterwards** (commit 723864a). → Once approved, changes go back as a listed amendment.
3. **Never build on an ambiguous answer.** "Approve a–e" where one item had two options: ask which, then build.
4. **Spec promises left undelivered without saying so** — `docs/modules/README.md` said "implemented". → Report what is not built.
5. **Check the spec's wording before changing an interface**, route, name or signature (I changed the Super Admin command's arguments against spec §1.6).
6. **Tell the owner what is happening every 20–30 minutes**; split a step that grows (3b ran ~2 h silently and the owner asked what I was doing).
7. **Numbered tables stay in order.** Amendment 37 was inserted above 36. → After inserting into a numbered table, print the numbers back.
8. **Follow the house voice.** I wrote the brand name into an email while every other message avoids it. → Read the neighbouring texts before adding one.
9. **One index line per memory.** Adding to `MEMORY.md`, update the existing line; do not create a second one for the same file.

## B · Design and contracts

10. **One signal must not mean two things** (`authorize($permission, ?StoreId)` meant both "no store" and "all stores").
11. **A contract must fit every consumer named in the handoff** (media: no customer upload, one id per call, no guest actor).
12. **Cross-cutting lists belong in a registry**, not one module's Domain (reserved paths lived in `StoreCode`).
13. **Design permanent data for redaction, provenance and import** from day one (audit log took raw setting values, always "now", no source).
14. **Never record an id the caller chose** (correlation id came from a header).
15. **Code refuses before the database.** Every CHECK, unique index and FK ships with a code rule and a test that the code refuses first (`media_checksum_format` had none).

## C · Security (the 3b reviews found nine holes I had written)

16. Build every emailed link on `APP_URL`, never on the request's Host header.
17. Count an attempt **before** the slow check, so parallel requests cannot all pass a limit.
18. A half-finished flow in the session carries the version of what it depends on, and re-checks the account when it continues.
19. A code counts only for the number or address it was sent to, and only while the account still has it.
20. Any change of phone, email, password or status kills every pending code, link and token tied to the old value.
21. "Disabled ends sessions" must survive re-enabling → raise the version.
22. A check behind a valid session (the current password) still needs a limit.
23. Anything answered "the same whether or not the account exists" must also **take** the same time (send the mail after the response).
24. PostgreSQL repeats values in its ERROR and CONTEXT lines, not only DETAIL.

## D · Laravel and framework traps

25. **Framework leftovers**: remove or adopt starter scaffolding deliberately (`users` table, `config/auth.php`).
26. **Laravel merges framework config back in** (`auth`, `cache.stores`, `queue.connections`): override an entry to disable it; deleting it does nothing.
27. **Resolve framework services by their contract**, never the concrete class (`Contracts\Http\Kernel`, not `Foundation\Http\Kernel`).
28. **Check the declared return type, not the runtime class** (`DatabaseStore::getConnection(): ConnectionInterface`).
29. **A provider's `$singletons`/`$bindings` apply after `register()` returns** — bind explicitly before using one inside `register()`.
30. **A guard in `boot()` runs where nothing is configured (2026-09-20).** The "production needs a real mailer" guard broke `composer install` (post-autoload-dump runs `package:discover`; with no `.env`, APP_ENV reads "production" and MAIL_MAILER "log") → CI red, and a fresh clone would fail. A boot guard must tolerate an unconfigured app (no `APP_KEY`), and CI installs `--no-scripts` → `.env` + key → `package:discover`. Check `.github/workflows/ci.yml` whenever boot behaviour changes.
31. **Per-store settings need a store context.** A handler reading one must run inside a store, and tests must wrap the call (`StoreContext::runIn`), or it throws `MissingStoreContext`.
32. **Platform's store middleware consumes `{store}` and `{locale}`** and turns them into URL defaults: a storefront controller takes neither parameter, and `route('storefront.home')` fills them in.
33. **Earlier steps leave deliberate "until step N" blocks** (the authorizer refused customers "until step 4"). → When starting step N, grep the code for that marker before writing anything new.
34. **PHPStan level 8 details**: no nullsafe on the left of `??`; no `is_array()` on a value already typed as array; chained `->not` needs care.

## E · PostgreSQL

35. **A CHECK that evaluates to NULL passes** → wrap JSON/nullable logic in `COALESCE(…, false)` and test the missing key.
36. **Laravel logs only successful queries**, so a query log cannot prove "the code refused first" → drop the constraint inside the test's transaction.
37. **One lock order everywhere** (roles → staff/assignments), plus `transaction(fn, 3)`; check the actor's right before looking ids up.
38. **jsonb does not keep key order** → compare decoded audit changes with `toEqualCanonicalizing`, never `toBe`.

## F · Tests

39. **Mutation-check every new guard**: remove each guarded line once and confirm a test goes red.
40. **Layered guards hide each other.** Test each layer with a case only that layer refuses; assert the side effect itself (the row is gone). Two layers that raise the same error need the data changed behind the handlers' back.
41. **Read a cache warm before the change**, or a "refresh" that was deleted still passes.
42. **Tests belong where the framework boots**: `tests/Architecture` has no Laravel; database and config tests go in `Integration`.
43. **Pest file functions and constants are global** → name them after the file's subject (two files declaring `console()` killed the run).
44. **A guard over files must assert it found something.**
45. **Verify every reviewer claim in the code before acting on it** (all three 3b reviews were right, but each was confirmed first; PostgreSQL's wording was confirmed by printing it).

## G · Tooling and environment (Windows)

46. **One test process at a time** against `touchwood_test`: two runs deadlock and look like flaky tests.
47. **Never pipe a long run into `Select-Object -First N`** — it stops the pipeline early and can leave the process running; write the output to a file and filter the file.
48. **When a run is slow, check the database container first**: `docker compose ps`. A stopped container makes pest hang for many minutes at ~5% CPU (17 minutes lost on 2026-09-20). Normal: whole suite ~2 minutes, PHPStan ~18 s, Pint ~2 s, Deptrac ~1 s.
49. **Backslashes and heredocs**: never edit PHP namespaces with sed, perl or an inline Python string (`\A`, `\N` explode). Use the Edit tool. PowerShell: `git commit -F -` takes no here-string (write a message file); `$false` is reserved.
50. **Merging a stacked PR with `--delete-branch` closes the PR built on it (2026-09-20).** #29 was based on #28's branch; merging #28 and deleting that branch **closed** #29, and GitHub refuses to reopen or retarget a PR whose base is gone. Recovery: push the old tip back to that branch name, reopen, `gh pr edit --base <parent>`, merge, then delete the restored branch. → Retarget the child PR to the parent's base **before** merging the parent, or merge the parent without `--delete-branch`.
51. **`composer check` has a 300 s process timeout** — a slow machine makes it fail there even when the suite passes; run `php vendor/bin/pest` directly to tell the two apart.

52. **One session store for the whole application (2026-09-20).** `app('session.store')` is a single object: a handler that writes to a session outside an HTTP request leaves that data in the next request's session, and two test browsers in one test share one store. A session adapter must read `$request->hasSession() ? $request->session() : null` and do nothing outside a request; a test browser must rebuild the store per request (`forgetDrivers()`, re-`instance()` it, `app('redirect')->setSession(...)`).
53. **Making a method nullable means guarding every caller (2026-09-20).** Changing `session()` to `?Session` and guarding only two of six callers broke two staff tests with "call to a member function forget() on null". → After widening a return type to null, grep every use in the class before running anything.
54. **PHPStan narrows a repeated call (2026-09-20).** `$this->x()?->a()` then `$this->x()?->b()` in the same branch is reported as "nullsafe on non-nullable" once the first result was proved non-null. → Take the value into a variable once and guard it.
55. **A signed-in actor cannot use a guest-only endpoint (2026-09-20).** A test that signs in and then posts to the sign-in route again gets "You do not have permission to do this" — the permission's audience is guests. → Use a new browser for a second sign-in in the same test.

56. **Never write back a row read outside its transaction (2026-09-20).** A repository `update()` writes every column, so a snapshot taken before a slow step (a password hash check) overwrites anything that committed in between — a reset, a block, a verification. Read again by id, under the lock, inside the transaction, and act on that object. Two independent reviewers found this in step 4b.
57. **A retried transaction closure must be self-contained (2026-09-20).** `transaction(fn, 3)` re-runs the closure: anything pulled before it (a model's `pullChanges()`, an early-returning setter) is already spent on attempt 2, so the write silently does nothing.
58. **One session table serves every area (2026-09-20).** Laravel sweeps old session rows with the lifetime of whichever request happens to trigger it, and deletes from one table: an admin request (12 h) would end a customer's remembered session (30 days). Give each area its own table when their lifetimes differ.
59. **Every route that shares a session cookie must share the middleware that sets its lifetime (2026-09-20).** One route left out (the email verification link) read the session under the framework's 2-hour fallback and signed remembered customers out.
60. **A test comparing against something always null proves nothing (2026-09-20).** "the cookie afterwards is not the cookie before" passed with session regeneration deleted, because the "before" cookie was null on a fresh browser. Assert the side effect (the old session row is gone).
61. **A guest-only permission refuses a signed-in actor (2026-09-20).** Sign-in, registration and password-reset pages are for guests, so a customer already signed in was refused their own reset link. Decide the rule per page (sign that session out first, or land them in the store) — do not leave it to the permission error.

62. **`json_encode([])` is `[]`, not `{}` (2026-09-20).** An empty map written to a jsonb column with a `jsonb_typeof = 'object'` CHECK is a row the database refuses. Cast to `(object)` when the column holds an object.
63. **Text a customer types reaches a shipping label (2026-09-20).** Refuse control characters and bytes that are not UTF-8 in any stored value: a newline adds a line to the label, a NUL byte is a row PostgreSQL refuses, and bad UTF-8 throws a JsonException with `JSON_THROW_ON_ERROR` - a 500 instead of a translated error. Trim first, so a pasted trailing newline is not refused.
64. **A unique violation is not retried (2026-09-20).** Laravel's `transaction(fn, 3)` retries deadlocks and serialization failures only, so a race into a partial unique index reaches the user as a raw QueryException. Hold the parent row (`FOR UPDATE`) for the whole transaction instead of counting or flag-setting unlocked.
65. **Normalise an id once, at the edge (2026-09-20).** A store id used raw for a cache key but lowercased for the query cached a copy that no later change invalidated. Read it into its value object at the top of the handler and use that string everywhere.
66. **Every comparison with NAN is false (2026-09-20)**, so a range check alone lets NAN through to the column. Use `is_finite()`.
67. **A per-request memo defeats a versioned cache (2026-09-20).** Keeping a store's format in a scoped mapper served the old copy after a change made in the same request. The cache is already the memo.
68. **A test whose subject has no data proves nothing (2026-09-20).** A "warm cache" test measured a customer with no addresses, so the code under test never ran; it passed with the cache deleted. Assert the result is not empty and that queries were made.

69. **Filter in the query, never after paging (2026-09-20).** A list that pages in SQL and drops rows in PHP returns short pages and a total that counts rows the reader may not see - a headcount is as revealing as a list. Push the visibility rule into the WHERE clause so the page and the total agree.
70. **A guard reachable only through a path another guard already blocks is untested (2026-09-20).** The "a Super Admin is never shown" rule survived its own deletion because the store rule hid them first. Set the data up so only the guard under test can refuse.
71. **One check is not a rule (2026-09-20).** An anonymized account could not sign in, but the password-reset flow looked only at the status, so it could still be sent a link and have a password written back. Every path that touches an account must ask the same question; the domain method should refuse too.
72. **A placeholder password must still look like a hash (2026-09-20).** `'anonymized'` works only because Laravel's bcrypt hasher does not verify the algorithm by default; a bcrypt-shaped string of dots is false for every password and safe if that setting is ever turned on.
73. **When the owner changes a rule, old tests assert the old rule (2026-09-20).** Revoking a Super Admin became "close the account" instead of "disable it": three tests in already-merged files had to be rewritten, and a database CHECK (a cancelled account keeps no password) caught what the domain method had forgotten.

74. **Inertia shares its props on the way in, before any route middleware (2026-09-24).** The application-wide `HandleInertiaRequests::share()` runs before the `web` group's siblings, so anything decided from the URL - the storefront's language - is not decided yet. An area that knows better must share it again from its own middleware, which is what ShareAdminPage already did and ShareStorefront now does. Symptom: `/sa/en` served in English inside `lang="ar" dir="rtl"`.
75. **A middleware that forgets a route parameter takes it from everyone downstream (2026-09-24).** `ResolveStore` calls `forgetParameter('store')` so generated URLs fill it in, so `$request->route('store')` is null in every later middleware and in every lazily-resolved prop. Read the request attribute it set instead.
76. **Cross-module reach is easy to write and deptrac catches it late (2026-09-24).** Access's storefront middleware imported Platform's `Presentation\Http\StorefrontLanguage`; the rule is Public/ only. Split the middleware by whose subject it is - Platform shares the store and the language, Access shares the shopper - rather than widening the ruleset.
77. **Python triple-quoted strings eat PHP escapes (2026-09-24).** Rewriting a test containing a `\u{...}` literal died with `truncated \uXXXX escape` and wrote nothing - twice, the second time while writing this very entry. Use raw strings (r-prefixed), or the Edit tool.
78. **A browser test reads the built bundle, not the source (2026-09-24).** Two new tests timed out looking for a `data-test` attribute added after the last `npm run build`. Rebuild before running the browser suite whenever the markup changed.

79. **A read model's key is not the column's name (2026-09-24).** `CustomerReader` answers `email_verified` (a boolean); asking it for `email_verified_at` gets null every time, so "your email is not confirmed" was true for everybody. Read the reader's `toRow()` before using a key.
80. **A test that asserts the falsy default passes for the wrong reason (2026-09-24).** `where('shopper.emailVerified', false)` was green while the value could never be anything else. Assert both ways round: set the state, then assert it flipped.
81. **Trimming a page's word list breaks its layout, silently (2026-09-24).** Removing `access::auth` from the store home was right that day and wrong the next, when the header started showing a name and a sign-out - the page then drew `access::auth.sign_out` on the screen while every suite called it green. The frame's words belong in one named list (`StorefrontArea::WORDS`), with a test per page that it carries them.

82. **A route parameter's name carries a global pattern (2026-09-25).** Platform sets `Route::pattern('store', ...)` for the shop's country code, so a panel route with `{store}` never matched a store **id**: 404, with nothing to say why. Name it `{storeId}` - or anything else - when it is not that kind of store.
83. **assertSee reads text, not input values (2026-09-25).** A browser test failed on a page that was drawing perfectly, because a field's name lived in an input. Read inputs with `script('document.querySelector(...).value')`.
84. **The browser suite keeps what it writes (2026-09-25).** A fixed phone number and a fixed field key both passed once and then failed for ever after - a number another customer holds is refused, and a repeated field key is refused. Every browser test makes its own data; run the suite twice before believing it.
85. **A toast is not an assertion (2026-09-25).** "Saved." fades after six seconds and loses races under load. Assert the row, or a value the page still holds.
86. **Presentation asking the authorizer is a decision (2026-09-25).** `tests/Architecture/AccessDecisionsTest` forbids `->authorize|allows|denies|storesWith|can|cannot` anywhere in a module's Presentation. What a reader may do belongs in an Application query (StaffActionsForReader, CustomerActionsForReader).

87. **RefreshDatabase hides every "must be inside a transaction" rule (2026-09-26).** It wraps each test in one, so Platform's audit log - which refuses an entry written outside the transaction of its change - was satisfied by the test harness itself. A handler with no transaction passed ten feature tests and threw a 500 the first time the owner pressed the button. Anything that checks `transactionLevel()` needs a **browser test**, which this suite deliberately does not wrap.
88. **A slow run is not a failing one (2026-09-26).** A browser test timed out at 5s in an 83-second run and passed in a 26-second one. Re-run before believing a timeout, and compare the durations - but never call it a flake without the second run to show for it.

89. **Raising a session version means refreshing the grants cache (2026-09-26).** `signedIn()` compares the session's version with the **cached** grants, not the staff row. Raise one without the other and the two disagree: every later sign-in stores the new number, is compared against the stale one, and is thrown out - the person is locked out of their own account until the cache expires. Every command that ends sessions does `$grants->refresh($staffId)` in the same transaction.
90. **A test for a destructive action must cover getting back (2026-09-26).** "Sign out everywhere" was tested by asserting they were signed out, and stopped there - so it proved the destruction and never noticed that signing in again was broken. Test the round trip, and check the test fails without the fix rather than assuming it would.

91. **A cookie written inside an admin request inherits path=/admin (2026-09-26).** Laravel's `cookie()` helper takes the current session's path, and UseAdminSession sets it to /admin - so the panel wrote `tw_locale` and `tw_theme` there while the shop wrote the same names at `/`. The browser then holds **two cookies of each name** and sends both, and which one PHP reads is the browser's choice: the toggle changed a copy nobody read. Give a site-wide cookie its path explicitly, and expire the twin. The same disease already had XSRF-TOKEN, which is why the CSRF token travels as a page prop.
92. **`AdminBrowser` keeps one slot per cookie name (2026-09-26)**, where a browser keys by name *and* path. A response that sets a name at `/` and clears it at `/admin` therefore looked like a deletion. It now treats a name set in a response as never also cleared by it; modelling paths properly is still not done.
93. **A mutation that did not apply reports a pass (2026-09-27).** A PowerShell `.Replace()` meant to swap `homeStoreId()` for `lastStoreId()` matched nothing, the file was unchanged, and the test "survived the mutation" — which briefly looked like a weak test. → Make the mutation with the Edit tool, and confirm the file changed (grep the line) before reading anything into the result.
94. **A new worktree has no built frontend (2026-09-27).** `composer install` + `npm ci` in a fresh worktree is not enough: every feature test that renders a page reads `public/build/manifest.json`, and 68 of them failed with "Vite manifest not found" while the code was fine. → After creating a worktree: copy `.env`, `composer install`, `npm ci`, **`npm run build`**, then test.
95. **PostgreSQL keeps 63 characters of a name (2026-09-27).** Laravel names a unique index `{schema}_{table}_{columns}_unique`, which for `b2b.application_documents (application_id, document_type_id)` ran past 63 and was cut to `…_uniqu` — a test searching the error for the full name failed while the rule itself held. → Name an index or constraint explicitly whenever the generated name could be long, and keep every CHECK name short.
96. **A new backed enum is a new TypeScript file (2026-09-27).** The transformer writes a type for every enum in a module's Public/Enums and Domain/ValueObject, and `GeneratedTypesTest` fails until the generated files are committed. → After adding an enum, run `php artisan typescript:transform` and commit what it writes, before the full check.
97. **A page prop with a shared prop's name silently replaces it (2026-09-27).** The account page's own `locale` (the staff member's communication language) was spread over the shared `locale` (the displayed language), so on that page only the language switch read the wrong one and was stuck on "English" — while `direction` and the words stayed with the display language. The #59 cookie fix was real but a different cause; the test fixture used the same language for both, so the clash was invisible. → Never reuse a shared prop's name for page data; test with the two values different; verify a reported UI bug by clicking it in a real browser on the page it was reported on.
98. **Claude in Chrome's element-reference clicks may not deliver a click (2026-09-27).** They focused the button but no click event reached the page; a click by screen position worked every time. → Click by position, and prove a click arrived with an in-page listener before calling a button broken.
99. **Another session can be editing the same checkout (2026-09-27).** Mid-task, 19 files I never touched turned up modified in the main checkout, and one of them failed Pint — so `composer check` stopped on someone else's work. → Run `git status` before the gate and before any commit; judge the gate against your own paths; `git add` only your own files, never `-A`; prove generated output against committed code (`git archive HEAD src app` into %TEMP%) when the tree is shared.
100. **Changing only the `#hash` never reloads a page (2026-09-27).** The browser pane kept running the old HTML/CSS while I measured "fixes" that were not loaded. → Reload with a cache-buster (`?v=N`) after editing a served file, and check the loaded CSS contains the change before measuring anything.
101. **Stripping comments shifts every offset (2026-09-27).** The catalog read doc comments from the original source at offsets found in the comment-stripped code, and 97% of summaries came out empty. → Map positions only within the text they were found in; look the declaration up again in the source.
102. **A phone-width check needs the viewport tag (2026-09-27).** A bare HTML page in the pane rendered at 980 px under "mobile" emulation, so it proved nothing; the artifact skeleton adds the tag at publish. → Test a copy wrapped the way it will be served, and scan every view (all 110 here) for `scrollWidth > clientWidth`, not a sample.
103. **PHPStan reads the tests too (2026-09-27).** Twice in a day a new test file failed the full check after passing on its own: values built in a mixed array lost their types, and an untyped closure given to `AssertableInertia::where()` could not be typed (it receives a `Collection` for an array prop - hint it). → Run `phpstan` on new test files before starting the ten-minute check.
104. **A code scanner is only as good as the call shapes it knows (2026-09-27).** My own checks of the action catalog passed; two independent reviewers still found four blind spots — `throw $failure` (error returned from a transaction closure, then thrown), `Job::dispatch()`, a cache held in a declared property or returned by a helper, `self::ATTEMPTS` — so `access.invalid_code` was missing from three actions and every "queued" list was empty. → Before trusting a generated map, list every way this codebase throws, queues, caches and calls (`grep` each shape), and cross-check the output in both directions (every audit key, event and error attached to something).

124. **`[IO.File]::ReadAllText`/`WriteAllText` ignore `Set-Location` (2026-10-02, Catalog step 1).** .NET static file methods resolve a relative path against the *process's* working directory — the tool shell's start folder (the main checkout), not the worktree PowerShell had moved to. A mutation script read a file that "did not exist", wrote an empty file into the **main checkout**, ran the tests on the untouched worktree and reported the mutant as survived. → Hand `[IO.File]` absolute paths only (`"$root\…"`), check `Test-Path` first, and treat a GREEN mutant as unproven until the file's diff is printed.
**How to apply:** before a step, re-read this list and design against it; when anything fails, add the entry immediately; when specifying a module, write its Public contract against every consumer in the handoff and mark every open choice as a question for the owner.
105. **`toEqualCanonicalizing` hides swapped from/to values (2026-09-28).** It sorts every nested array too, so an audit change `[from, to]` compared that way cannot tell `null → b2b` from `b2b → null`. A mutation that flipped them stayed green. → Compare audit changes with `ksort` + `toBe`; refines lesson 38.
106. **A browser test that reads "the newest N" breaks as rows pile up (2026-09-28).** The browser suite keeps its data, and "Currency added" (seeded) fell off the audit log's first 50 once new tests signed in more often. → Open the screen filtered to what the test asserts (`/admin/audit?action=…`), never rely on the unfiltered first page.
107. **The Pest browser plugin can hang before it reaches Playwright (2026-09-28).** Playwright's run-server says "Listening", but pest sits idle, with no test-database session, until the 10-minute command limit. About seven hangs on 2026-09-28. My first guess — "a build in the same shell command" — was **refuted**: the integrator's and my 22:11 run hung with the build in a separate, earlier command. What held every time: the re-run in a fresh command passed (16–23 s for one file). Playwright's "Listening on" line was in `%TEMP%\sf_proc_00.out`, but pest held no TCP connection at all. Cause unknown. → If a browser run shows no DB session and no CPU after ~2 minutes, stop only your own run (pest, its cmd.exe child, the playwright node) and re-run it in a fresh command; count it, report it, and do not call the code broken. Again 2026-09-29 (failed jobs): a run of one file by path hung 10+ minutes; the re-run in a fresh command with `--filter` passed in 6 s — path-vs-filter is no more proven than the build guess was.
108. **A workflow agent can be cut off by the machine, not by the work (2026-09-28).** Wi-Fi drops killed the 3a builders twice mid-edit, and a later outage of the auto-mode safety check blocked every shell command, so builder F returned "blocked" with all its work staged. A restarted builder reuses whatever its predecessor left, including a stash (stashes are repo-wide). → On any agent failure, read its log before believing the status; finish its last steps by hand only after re-running its checks; say in the builder prompt whether to reuse or discard leftovers.
109. **A query recorder must match the SQL the code really sends (2026-09-29).** To prove "refused before anything is stored" I counted `insert into "platform"."media"` queries — but Platform writes media with its own raw `INSERT INTO platform.media … ON CONFLICT`, so the counter never moved and every "0 writes" assertion was empty. A positive check (a real upload must count 1) caught it before any mutation run. → Give every recorder a positive case first; match SQL case-insensitively and in both quoted and raw forms.
110. **"Untestable in one process" was wrong about a lock (2026-09-29).** In 3b I marked "remove the account lock" as a mutation no test could catch, and wrote in the README that the lock "cannot be proved". Reviewer B showed otherwise: a `DB::listen` recorder that notes every `pg_advisory_xact_lock(_shared)` with its key and `DB::transactionLevel()` proves the lock is taken, and taken inside the use case's own transaction (level 2 under RefreshDatabase). The new test caught the lock removed (6 red), the transaction removed (1 red), and exclusive swapped for shared. → Before calling any guard untestable, look for what it leaves behind — a query, its bindings, its transaction level — and record that; lesson 87's trick generalises to locks.
